# 训练全流程

> 本文描述从本地代码到服务器训练、续训、评测的完整链路。所有脚本面向 Linux 服务器（bash），默认使用第 2/3/4/5 张 A800，支持 2~4 卡。

## 1. 总体数据流

```text
任务 parquet ──► 环境 worker(ray) ──► 多轮 rollout（vLLM 生成每轮动作）
                                          │
                                          ▼
                          episode_rewards（可验证结果, 0/1）
                                          │
                                          ▼
              ┌── student 前向（无技能）: old_log_probs
              └── teacher 前向（技能 c⁺）: teacher_log_probs  ──► δ=teacher−student
                                          │
                                          ▼
              AgentOPSD 信用模块（credit.py）
              e_k → 递归信念 B_k → ΔB_k → q_k → w_k → Ã_k
                                          │
                                          ▼
              裁剪 GRPO 目标（每 token 继承所属轮次 Ã_k）──► FSDP 参数更新
                                          │
                                          ▼
              save_freq 存断点 ──► 可断点续训；test_freq 跑验证集 ──► 稳定性曲线
```

## 2. 本地开发 → 服务器（ssh git）

本地只保存**代码**（`.gitignore` 已排除数据、权重、断点、日志、SDAR vendor 等一切大文件）。

```bash
# 本地首次
git init
git add -A && git commit -m "init"
git remote add origin ssh://<user>@<server>/~/git/AgentOPSD.git   # 服务器端 git 仓库地址

# 之后每次同步（也可用仓库内脚本）
bash scripts/git_sync.sh
```

服务器端：

```bash
git clone <上述 remote> && cd AgentOPSD
bash scripts/setup_server.sh          # 见下一节
```

## 3. 服务器环境配置（uv + CUDA-12-conda）

服务器已具备：`CUDA-12-conda` 环境、vllm、flash-attn、deepspeed、IPC。本仓库用 **uv** 在同一个 conda 环境里管理 Python 依赖，避免重装 torch/vllm。

`scripts/setup_server.sh` 会做：

1. `conda activate CUDA-12-conda`；
2. 安装 `uv`（`python -m pip install uv`）；
3. 克隆 SDAR 基座到 `vendor/SDAR`（固定 master，可用 `--sdar-commit <hash>` 钉版本）；
4. `uv pip install -e .`（本项目）和 `uv pip install -e vendor/SDAR`（SDAR 依赖；torch/vllm/flash-attn 已存在则跳过）；
5. 自检：torch CUDA、vllm、flash_attn、deepspeed 版本、GPU 数量、`/dev/shm` 大小（IPC）。

要点：

- 不要用 `uv sync` 创建新 venv——那样会与 conda 里编译好的 CUDA 轮子隔离。这里 **uv 只负责往当前 conda 环境装依赖**。
- ALFWorld 额外需要 `gymnasium==0.29.1 stable-baselines3==2.6.0 alfworld`（`prepare_data.sh` 自动装）。
- WebShop 需要 Python≤3.10 独立环境；Search-QA 需要独立的 faiss-gpu 检索服务——两个都在 `prepare_data.sh` 里给出精确步骤。
- IPC：训练需要大共享内存（vLLM 多进程 + Ray）。确认 `df -h /dev/shm` 有足够空间（建议 ≥ 32GB），必要时 `--shm-size` / 挂载扩容；vLLM 的 `use_shm=True` 选项可把模型权重放共享内存加速加载。

## 4. 数据获取

### 4.1 ALFWorld（默认）

```bash
bash scripts/prepare_data.sh alfworld
```

实际执行：

1. 安装 gymnasium/stable-baselines3/alfworld；
2. `alfworld-download -f`（PDDL/Game/预训练检测器 → `~/.cache/alfworld`）；
3. `ALFWORLD_DATA=$DATA_ROOT/alfworld`，在 SDAR 下运行 `examples.data_preprocess.prepare --mode text` 生成占位 parquet：
   `$DATA_ROOT/verl-agent/text/{train,test}.parquet`（行数=任务数；具体任务在 rollout 时由环境实例化）。

> 注意：`prepare.py` 需要从 HF 拉 `hiyouga/geometry3k`（只用它定行数），服务器设 `HF_ENDPOINT=https://hf-mirror.com` 加速。

### 4.2 WebShop / Search-QA

`prepare_data.sh webshop|search` 会打印 SDAR 官方步骤（WebShop 需 Python≤3.10 的 `verl-webshop` 环境；Search 需 `retriever` 环境 + faiss-gpu + E5 索引 + 常驻检索服务，约占每卡 6GB 显存，注意给训练留余量）。

## 5. 模型下载

```bash
bash scripts/download_model.sh Qwen/Qwen3-8B-Instruct
```

默认走 `hf-mirror.com`，HF 不通时自动切 ModelScope；GitHub 镜像/LFS 方案见 [model/download_model.md](../model/download_model.md)。下载后训练脚本自动识别 `$MODEL_CACHE/Qwen3-8B-Instruct`。

## 6. 训练（2~4 卡，设备 2-5，断点续训）

### 6.1 单次训练

```bash
cd AgentOPSD
bash scripts/train.sh                                  # 4 卡：CUDA_VISIBLE_DEVICES=2,3,4,5，150 步
```

常用参数（`scripts/configs/agentopsd.env` 全部可覆盖）：

| 参数/环境变量 | 说明 | 默认 |
|---|---|---|
| `CUDA_VISIBLE_DEVICES` | 用哪几张卡 | `2,3,4,5` |
| `N_GPUS` | 卡数（2~4，留空自动推导） | 自动 |
| `MODEL_NAME` | 模型 | `Qwen/Qwen3-8B-Instruct` |
| `ENV_NAME` | 环境 | `alfworld` |
| `TRAIN_STEPS` / `SEED` | 步数 / 随机种子 | 150 / 0 |
| `AGENTOPSD_ENABLE` | 1=AgentOPSD，0=纯 GRPO 对照 | 1 |
| `AGENTOPSD_LAM/B/GAMMA` | λ/b/γ | 0.5/0.2/0.95 |
| `RESUME_MODE` | `auto`/`resume_path`/`disable` | `auto` |
| `SAVE_FREQ` / `TEST_FREQ` | 存断点/验证频率 | 10 / 5 |
| `MICRO_BATCH_PER_GPU` | FSDP 微批，OOM 时调小 | 16 |

命令行覆盖示例：

```bash
bash scripts/train.sh --steps 50 --seed 1
bash scripts/train.sh --gpus 2,3 --steps 50            # 2 卡
bash scripts/train.sh --disable-credit                 # GRPO 对照（ablation）
SEED=2 AGENTOPSD_LAM=0.25 bash scripts/train.sh        # λ 敏感性
```

### 6.2 断点续训（本项目硬性要求）

训练每 `SAVE_FREQ` 步把 actor（FSDP 分片）、optimizer、dataloader 状态存到
`checkpoints/<实验名>/global_step_<N>/`，并写 `latest_checkpointed_iteration.txt`。

三种续训语义：

```bash
# 1) auto（默认）：找到最近的 global_step_* 自动续训；没有就从头
RESUME_MODE=auto bash scripts/train.sh

# 2) resume_path：显式指定断点
bash scripts/train.sh --resume-ckpt checkpoints/xxx/global_step_40

# 3) disable：忽略旧断点，强制从头（会覆盖同名实验的断点，慎用）
bash scripts/train.sh --fresh
```

续训会恢复 `global_steps`、优化器状态和 dataloader 进度，成功率曲线无缝衔接。稳定性验收里包含"中断→续训→曲线一致"的专项测试（见 04 文档）。

### 6.3 训练期间自动验证

每 `TEST_FREQ` 步用验证集（默认 128 个任务）跑一次，vLLM 采样温度 0.4，输出 `val/success_rate` 等指标到 console/wandb，这是稳定性曲线的主要来源。

### 6.4 8B 显存估算（A800 80GB）

- actor FSDP：8B bf16 权重 ~16GB + 优化器（Adam）~32GB，4 卡 FSDP 分摊后每卡 < 20GB；
- vLLM rollout：TP=2，`gpu_memory_utilization=0.6`，每卡约 48GB 上限但实际远小于此；
- 总占用典型 < 65GB/卡，留出 env worker 与缓存余量。OOM 时依次：`MICRO_BATCH_PER_GPU` 减半 → `GPU_MEM_UTIL` 降到 0.5 → `ENV_CPUS` 保持 0.1。

## 7. 评测

### 7.1 训练中评测

`TEST_FREQ` 自动完成，无需手工操作。

### 7.2 独立评测（任意断点）

```bash
bash scripts/eval.sh --ckpt checkpoints/xxx/global_step_40
```

等价于加载断点后只跑一次 `_validate()`（不更新参数），输出每个验证任务的得分与总体 `val/success_rate`。评测也需要数据 parquet 存在。

### 7.3 合并断点为 HF 权重

```bash
bash scripts/merge_checkpoint.sh checkpoints/xxx/global_step_40
```

用 SDAR 的 `model_merger.py` 把 FSDP 分片合并成标准 HF safetensors，用于下游推理/发布。

## 8. 稳定性观测与报告

```bash
# 跑实验矩阵（多 seed × λ）后自动生成报告
SEEDS="0 1 2" LAM_SWEEP="0.5 0.25 0.1" bash scripts/run_stability_matrix.sh

# 或只对已有日志生成报告
python3 scripts/stability_report.py --root logs --out report.md
```

报告解析 `logs/<实验>/train.log` 中 `step:N - key:value` 行与 `[agentopsd] {...}` JSON 行，汇总最终验证成功率/熵/信用诊断，并给出 NaN、量级异常、末期跳变告警。指标定义与判定标准见 [04-训练稳定性评测方案](04-训练稳定性评测方案.md)。

## 9. 常见问题（FAQ）

| 现象 | 处理 |
|---|---|
| vLLM 启动 OOM | 降低 `GPU_MEM_UTIL`；确认没有别的进程占用 2-5 卡（`nvidia-smi`） |
| Ray worker 卡在注册中心 | `trainer.ray_wait_register_center_timeout=600` 已内置；检查 `ulimit`/IPC 与防火墙 |
| `/dev/shm` 不足 | 扩共享内存（Docker 加 `--shm-size=64g`）；必要时 `actor_rollout_ref.model.use_shm=False` |
| HF 下载失败 | `HF_ENDPOINT=https://hf-mirror.com` 已默认；换 ModelScope：`MODELSCOPE_ENABLED=1 bash scripts/download_model.sh` |
| 续训后曲线跳变 | 确认 `RESUME_MODE=auto` 与相同的 `EXPERIMENT_NAME`（自动由模型/环境/λ/seed 生成）；检查 `global_step_*` 目录是否被清 |
| 训练 loss 出现 NaN | 查 `logs/.../train.log` 的 `[agentopsd]` 行与 `actor/...` 指标；降低 LR、检查 `AGENTOPSD_SUCCESS_THRESHOLD` 是否符合环境奖励刻度 |
| 想严格复现论文 | `MODEL_NAME=Qwen/Qwen2.5-7B-Instruct`，其余超参即论文 Table 3/4 |
