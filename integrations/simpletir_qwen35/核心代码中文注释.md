# SimpleTIR Qwen3.5 核心代码中文注释

本目录的执行路径是：`main_tir.py` 读取 Hydra 配置，`agent_loop_manager.py`
将一个 batch 拆成 TransferQueue 会话，`simpletir_agent_loop.py` 为每个会话
生成“模型输出 → Python 沙箱观察 → 下一轮模型输出”的轨迹，随后 `trainer.py`
计算 GRPO 或 AgentOPSD 优势并执行 actor 更新。训练题的标准答案始终只留在
`reward_model.ground_truth`：学生 prompt、沙箱观察和普通日志都不包含它。

下面按源码中每一段会改变数据、张量或控制流的语句说明；导入、空行及纯类型
标注不重复解释。

## `main_tir.py`：启动与训练前约束

1. `compose_config` 从已安装 Verl 的 `trainer/config/ppo_trainer.yaml` 组合配置，
   因而本项目只覆盖 SimpleTIR 行为，不复制或漂移上游 PPO 基础配置。
2. `main` 调用 `auto_set_device`、`validate_config`，先验证设备、reference policy
   与 critic 依赖，再启动 Ray。
3. `use_v1`、`trainer_mode=sync`、TransferQueue、FSDP size 与 GPU 数的检查是硬
   约束；错误配置在分配 GPU 前失败。
4. `validate_simpletir_files` 逐行验证 Parquet schema。它只返回列名与行数，避免
   将题目或答案写进日志。
5. `SIMPLE_TIR_PREFLIGHT_ONLY=1` 用于不占 GPU 的数据/配置预检；其余情况由
   `run_ppo` 创建远程 `SimpleTIRTaskRunner`。
6. runner 中 `trainer.init()` 建立 actor、reference 与 rollout 服务；manager 创建后
   `trainer.fit()` 才会消费 rollout。`finally` 总会结束 tracker 并关闭 TransferQueue。

## `simpletir_agent_loop.py`：一条多轮轨迹

1. `_sandbox_limiter` 以 `(event loop id, 并发上限)` 缓存 semaphore，限制同一个
   Ray worker 同时提交的 systemd/bwrap 沙箱数。
2. `_safe_rollout_extra_fields` 只转发调度步数，不复制 prompt、模型代码或答案。
3. `_as_token_id`、`_as_logprob` 解开 vLLM top-k 的 singleton 维；不是 singleton
   就报错，防止 teacher log-prob 与学生 token 错位。
4. 构造 `SimpleTIRPythonAgentLoop` 时，配置最大轮数、沙箱超时、观察截断与并发，
   并立即拒绝不合法上限。
5. `run` 先将上游 SimpleTIR tool-use 前缀加到学生消息，再用 chat template 得到
   初始 token。`episode_text` 保存每轮学生文本与受限观察，专供最终数学评分。
6. 每个 turn 调用 rollout server；`ct_merge_assistant_token` 同时得到 prompt ids、
   response ids、mask 和 rollout log-prob，随后构造一条真实 `AgentLoopOutput`。
7. AgentOPSD/OPSD 的训练回合才调用 `_same_policy_teacher_logprobs`。标准答案仅在
   私有 teacher system message 中出现，返回值只有逐 token 的浮点 log-prob。
8. 有 fenced Python 时，通过 semaphore 在线程中运行 `run_python`，将 stdout/stderr
   格式化为至多 `max_observation_chars` 的下一轮用户观察。
9. `final_answer()` 或模型最后的 `\\boxed{}` 会终止轨迹；无代码也无 boxed answer
   的 void turn 同样终止，但它本身仍是一条真实 rollout row，绝不伪造 padding。
10. 最后才读取 `ground_truth` 并调用 `score_simpletir_math`。终端 reward 写在最后一
    条输出，后续由 manager 广播给同一会话已存在的 turn rows。

## `simpletir_sandbox.py`：不可信代码的隔离

1. `_systemd_environment` 仅保留启动 user systemd 所需的 PATH、D-Bus 变量；模型
   进程仍会被 bwrap 的 `--clearenv` 清空环境。
2. `_sandbox_venv` 只读挂载科学计算 venv，使 numpy/sympy 可用但宿主数据盘不可见。
3. `_bwrap_command` 使用 `--unshare-all`、新 session、只读系统库、tmpfs `/tmp` 和
   空 `/work`，并把 BLAS 线程固定为 1。
4. `run_python` 再由 `systemd-run` 施加任务数、内存、CPU、文件数和文件尺寸上限；
   GNU `timeout` 与外层 `subprocess.run(timeout=...)` 共同确保 worker 不会永久阻塞。
5. 退出码 124/137，或接近时限的 255，标记为 timeout；立即发生的 255 被保留为
   配置错误，避免把宿主故障误统计成模型超时。

## `agent_loop_manager.py`：TransferQueue 行协议

1. `generate_sequences` 从 batch 读取 `validate`，但只将 boolean 传给自定义 loop；
   teacher 在 validation 永远不调用。
2. `_run_prompt` 为每个样本建立 n 个 session，等待所有 session 完成后再写入
   `finished` 或 `failure` 状态。
3. `_agent_loop_postprocess` 对真实输出计算 reward、广播终端 reward，并为每一轮构造
   `input_ids`、`response_mask`、text-only `position_ids` 与 `loss_mask`。
4. 每一轮对应一个 `uid_session_turn` key。`async_kv_batch_put` 只发布该 loop 实际
   生成的 rows；它没有为填充复制任何 turn。

## `trainer.py`：三组消融的分界

1. `SimpleTIRTrainer` 只接受 `grpo`、`opsd_author_code`、`agentopsd` 三种 method。
2. `_balance_batch` 允许 Verl 增加 response mask 全零的 actor padding，但检查所有
   非 padding key 仍是原 key 的排列，防止历史上的真实 turn 复制错误。
3. `_write_teacher_response_logprobs` 对每条非 padding row 检查 token 长度、有限性、
   `turn_step` 与 `uid_session_turn` 对齐，并把密集 teacher tensor 转回 nested 格式。
4. `_reshape_agentopsd` 先确认同一 session 的 GRPO advantage 原本一致，再以 teacher
   与 student log-prob、成功标签、turn 索引调用 `reshape_advantages`；结果覆盖
   `advantages` 和 `returns`。
5. `_compute_advantage` 的分支是消融核心：GRPO 直接返回上游优势；OPSD 写入 teacher
   分数但不重塑 GRPO 优势；AgentOPSD 再执行 turn-level advantage reshaping。
6. `_compute_metrics` 只写聚合比例、数值诊断与验证指标。没有题目、程序 stdout 或
   ground truth。

## `trajectory.py` 与 `opsd_loss.py`

1. `extract_last_boxed` 不用正则嵌套匹配，而是逐字符数花括号，能正确处理嵌套 LaTex。
2. `score_simpletir_math` 先用 `math_verify`，再以 `sympify` 回退处理 Python 风格表达式；
   在线程内禁用依赖 SIGALRM 的 parser timeout，避免正确答案被吞成零奖励。
3. 正确但没有实质工具调用时 reward 减半；`answer_accuracy` 仍保持二值，供
   AgentOPSD 的 B0 成功标签使用。
4. `sdar_only_loss` 是 author-code OPSD 基线：gate detach 后，只让
   `-student_log_probs` 接收梯度；它明确没有任务奖励 policy-gradient 项。
